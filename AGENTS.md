## Learned Workspace Facts

- Local full stack: from repo root run `python -m api.app` for Flask (port 5001); from `frontend/` run `npm run dev` for Vite (port 5173). Use the app at 5173; Vite proxies `/api` to 5001. OpenAPI docs live at `http://localhost:5001/api/docs`.
- Test discovery has pre-existing `bcrypt` import errors in `tests/api/test_jwt_auth.py` and `tests/api/test_runs.py`; install `bcrypt` in the active Python env when auth is needed, otherwise run `python -m pytest tests/unit/...` to avoid the collection failure.
- This is a Windows/PowerShell environment — PowerShell does not support `&&` for sequential commands. Chain commands via separate Shell calls or `;` (no short-circuit), or use Python one-liners; do not assume bash-style command chaining.
- JetDrive live capture ordering is sensitive; `api/routes/jetdrive/hardware.py` (`_live_capture_loop.on_sample`) is the place to keep sample canonicalization consistent. Live wideband/JetDrive streams are not always trustworthy; when the user says a channel is bad or stuck, fall back to exported WinPEP8 or text logs for analysis.
- DynoWare's `LC2 Volts Petrol AFR2` (and similar `*Volts*AFR*`) channels are already in AFR units despite the "Volts" label — do NOT re-apply a volts->AFR rescale. Innovate LC rail/ceiling is 22.39; values >= 22.38 are pegged/sensor-faulted and must be excluded from AFR analysis (annotate, don't delete from raw logs). Venturi/tailpipe widebands are also bulk-AFR mixed-cylinder readings, so front-vs-rear splits derived from them are invalid; apply the same correction to both VE tables. True per-cylinder splits require per-cyl head-pipe sniffers.
- DynoWare run-config "RPM Source" must be calibrated against a steady non-zero RPM in the target gear before any HP/TQ pull is trusted. For bikes whose dash shows only MPH, use the ECU `Engine Speed` channel through DynoWare as `Software Defined`; calibrating while the value reads 0 produces garbage HP/TQ (e.g. 1000+ hp).
- Some bikes have no O2 sensors installed; codify per-vehicle constraints under `vehicles/<vid>/profile.json` `tuning_guardrails` (e.g. `no_o2_sensors_on_bike: true`, `afr_source: "dyno_tailpipe_wideband_only"`, `watch_folder` for incoming dyno logs) and have the patch generator and any autotune logic read from there rather than relying on global defaults.
- When stock ECU or download baselines disagree on displacement, stoich, or fuel table references, reconcile against the user's stated hardware and fuel before trusting a single file's defaults; a wrong displacement in the base tune masks itself by inflating VE during autotune. Record both `base_tune_sha256` (OEM) and any stage tune SHA (e.g. `dynojet_stage_sha256`) in `session.json`.
- PVV (PowerVision XML) tune files MUST be edited surgically with stdlib `xml.etree.ElementTree.parse` + `tree.write` — the existing `parse_pvv_tune` / `generate_pvv_xml` round-trip in `api/services/powercore_integration.py` drops Item `id` attributes and produces flash-unsafe output. Find Items by `name`, mutate only target cells, write back. Always inspect axis labels in the actual `.pvv` first — tables that look MAP-based may be TPS-based, and tables like `tbl_pe_spark` can be all-zeros / unused on a given ECU; never assume axis semantics from the table name alone.
- Tune iteration layout: base tunes live under `vehicles/<vid>/sessions/<sid>/base_tune/` with SHA-256 recorded in `session.json`. Iter_N artifacts live under `iterations/iter_N/{patch,pulls,analyses}/`. Findings JSON for iter_(N+1) lives at `iter_N/analyses/iterN_*_findings.json`. Patch generators (e.g. `tools/generate_iterN_patch.py`) import iter_(N-1) helpers, add ONE new correction pass + ONE new verification gate per iteration, must be idempotent (same inputs -> same SHA-256), and MUST abort without writing if any gate fails. Per-cell clamps are mandatory (e.g. spark +/-3 deg, VE +/-10% of base, displacement exact).
- Dyno pulls arrive as a pair: DynoWare `.txt` (CSV, the only programmatically diff-able form for AFR analysis) and WinPEP8 `.wp8` (binary, provenance only). `.txt` goes under `iter_N/pulls/` and `.wp8` under `iter_N/pulls/raw_wp8/`. Maintain a single append-only `manifest.json` per iteration with SHA-256 of each file that is idempotent on re-ingest. Dynojet `.djt` exports remain encrypted/binary; the `.pvv` PowerVision export is the only programmatically diff-able tune representation.
- Power deltas alone are NOT a reliable trigger for the next iteration — run-to-run variation on 4th-gear loaded pulls easily covers +/-3-5 hp. Only iterate when an AFR error pattern in a given zone is consistent across multiple clean pulls AND was captured in the post-flash data set (not pre-flash). Generated-but-never-flashed iterations (e.g. iter_2 v3) are superseded by the next single-flash candidate and should be marked as such in the session.
